@Test(priority = 1, description = "TC_001: Valid login → Dashboard") public void testValidLogin() { navigateToLoginPage(); fillLoginForm(VALID_USERNAME, VALID_PASSWORD); clickLoginButton(); // Wait for Dashboard heading to appear WebElement dashboard = wait.until( ExpectedConditions.visibilityOfElementLocated( By.xpath("//h6[contains(text(),'Dashboard')]") ) ); Assert.assertTrue(dashboard.isDisplayed()); // Verify URL left login page Assert.assertFalse(driver.getCurrentUrl().contains("auth/login")); }
@Test(priority = 2, description = "TC_002: Invalid password → error alert") public void testInvalidPasswordLogin() { navigateToLoginPage(); fillLoginForm(VALID_USERNAME, INVALID_PASSWORD); clickLoginButton(); // Assert error alert is visible WebElement error = wait.until( ExpectedConditions.visibilityOfElementLocated( By.cssSelector(".oxd-alert-content-text") ) ); Assert.assertTrue(error.isDisplayed()); Assert.assertTrue(error.getText().contains("Invalid credentials")); }
@Test(priority = 3, description = "TC_003: Empty fields → required validation") public void testEmptyFieldsLogin() { navigateToLoginPage(); // Submit without filling anything clickLoginButton(); // Assert "Required" validation message WebElement required = wait.until( ExpectedConditions.visibilityOfElementLocated( By.cssSelector(".oxd-input-field-error-message") ) ); Assert.assertEquals(required.getText(), "Required"); }
How to host & showcase
1

Create a GitHub repo

Go to github.com → New repository → name it selenium-login-demo → make it Public.

2

Upload all project files

Push the full Maven project. The structure must include pom.xml, src/, and .github/workflows/.

$ git init && git add . && git commit -m "Initial commit"
$ git remote add origin https://github.com/YOUR_USERNAME/selenium-login-demo.git
$ git push -u origin main
3

GitHub Actions runs automatically

Every push triggers the workflow. Go to Actions tab on your repo — you'll see the tests running live with Chrome.

4

Add a "Run workflow" button (manual trigger)

The workflow_dispatch: in the YAML enables a manual trigger. Visitors can click Run workflow directly from the Actions tab to see it execute live — perfect for demos.

5

Add the status badge to README

Copy the badge URL from Actions → your workflow → ⋯ → Create status badge and paste into README.md. It shows green/red live status.

6

Link from your portfolio

Add a "Live Demo" button on your portfolio site pointing to the GitHub Actions URL. Recruiters can watch the tests run in real time — no local setup needed.

https://github.com/YOUR_USERNAME/selenium-login-demo/actions
7

Download test report artifact

After each run, GitHub stores the TestNG HTML report as a downloadable artifact for 30 days. Share the direct artifact link as proof of results.
